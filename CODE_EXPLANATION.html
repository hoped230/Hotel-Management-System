HotelManagementSystem.java — Code Explained

A simple breakdown of what each part of the code does, written for easy understanding

Overview: What This File Contains

The entire application is in one Java file. It has 15 classes/interfaces organized in this order:

Enums (RoomType, RoomStatus) → Interfaces (Billable, Displayable) → Abstract Room class → Room subclasses (Standard, Deluxe, Suite) → DataStore (Generics) → Bill (Wrappers) → BookingQueue (Threading) → FileManager (File I/O) → Hotel (Collections) → HotelManagementSystem (JavaFX App)
A restaurant. The enums are the menu. The Room classes are the tables. The Hotel class is the manager. FileManager is the record book. And HotelManagementSystem is the front desk that customers interact with.

1. Enums — RoomType & RoomStatus

What is an Enum?

An enum is a fixed set of constants. Instead of writing "Standard" or "Deluxe" as strings (which you could misspell), you define them as enum values that the compiler enforces.

enum RoomType {
    STANDARD("Standard", 1500.0),   // Each constant has a name and price
    DELUXE("Deluxe", 3000.0),
    SUITE("Suite", 5000.0);

    private final String displayName;
    private final double pricePerDay;

    // Enum constructor — called once for each constant
    RoomType(String displayName, double pricePerDay) { ... }

    // Enum methods — called like RoomType.DELUXE.getPricePerDay()
    public double getPricePerDay() { return pricePerDay; }
}

enum RoomStatus { AVAILABLE, OCCUPIED }  // Simple enum, no fields

How it's used: When creating a room, you say RoomType.DELUXE instead of a string. To get the price, you call RoomType.DELUXE.getPricePerDay() which returns 3000.0.

2. Interfaces — Billable & Displayable

What is an Interface?

An interface is a contract. It says "any class that implements me MUST have these methods." The interface doesn't say HOW to do it — just WHAT must exist.

interface Billable {
    double calculateBill();     // Any Billable class must have this
    String getBillDetails();   // And this
}

interface Displayable {
    String getDisplayInfo();   // Any Displayable class must have this
}

Who implements them: The Room class implements both. So every room MUST have calculateBill(), getBillDetails(), and getDisplayInfo() methods.

3. Abstract Class — Room

What is an Abstract Class?

An abstract class is a blueprint that can't be used directly. You can't write new Room(101, ...). You MUST create a StandardRoom, DeluxeRoom, or SuiteRoom instead. It defines common fields and methods that all rooms share.

abstract class Room implements Serializable, Billable, Displayable {

    // ENCAPSULATION — fields are private, accessed via getters
    private int roomNumber;
    private RoomType roomType;
    private RoomStatus status;
    private String guestName;
    private String guestPhone;
    private int daysBooked;

    // CONSTRUCTOR — sets up a new room
    Room(int roomNumber, RoomType roomType) {
        this.roomNumber = roomNumber;  // 'this' refers to the current object
        this.roomType = roomType;
        this.status = RoomStatus.AVAILABLE;
    }

    // CONSTRUCTOR OVERLOADING — same name, different parameters
    Room(int roomNumber, RoomType roomType, String guestName, ...) {
        this(roomNumber, roomType);  // calls the first constructor
        this.guestName = guestName;
    }

    // GETTERS — public access to private fields
    public int getRoomNumber() { return roomNumber; }

    // METHOD OVERLOADING — two versions of bookRoom
    public void bookRoom(String name, String phone) {
        bookRoom(name, phone, 1);  // default 1 day
    }
    public void bookRoom(String name, String phone, int days) {
        this.status = RoomStatus.OCCUPIED;
        this.guestName = name;
        ...
    }

    // ABSTRACT METHOD — subclasses MUST implement this
    abstract double getServiceCharge();

    // POLYMORPHISM — this method can be overridden by subclasses
    @Override
    public double calculateBill() {
        return roomType.getPricePerDay() * daysBooked + getServiceCharge();
    }
}
A form template. The Room class is like a blank hotel registration form. It has all the fields (room number, guest name, etc.) but you need a specific type (Standard/Deluxe/Suite) to actually fill it out.

Key OOP concepts here:

  • Encapsulation: Fields are private, only accessible through getters — outsiders can't change room data directly
  • this keyword: Refers to "this current object" — used when parameter names match field names
  • Method Overloading: Two bookRoom() methods with different parameters
  • Abstract method: getServiceCharge() has no body — each subclass defines its own
  • Serializable: Lets us save Room objects to a file

4. Room Subclasses — Standard, Deluxe, Suite

What is Inheritance?

These classes extend Room, meaning they inherit all of Room's fields and methods, but can add their own behavior. This is the "is-a" relationship: a DeluxeRoom IS A Room.

class StandardRoom extends Room {
    StandardRoom(int roomNumber) {
        super(roomNumber, RoomType.STANDARD);  // 'super' calls parent constructor
    }

    @Override
    double getServiceCharge() { return 0; }  // No extra charge

    @Override
    public String getDisplayInfo() {
        return super.getDisplayInfo() + " - Basic";  // super.method() calls parent's version
    }
}

class DeluxeRoom extends Room {
    private double extraCharge = 500.0;

    @Override
    double getServiceCharge() { return extraCharge; }  // Rs. 500 extra
}

class SuiteRoom extends Room {
    private double discountRate = 0.10;

    @Override
    double getServiceCharge() {
        return -(getPricePerDay() * getDaysBooked() * discountRate);  // 10% discount (negative charge)
    }
}

This is Polymorphism in action: When calculateBill() is called, it calls getServiceCharge() — but the actual method that runs depends on which type of room it is. StandardRoom returns 0, DeluxeRoom returns 500, SuiteRoom returns a negative number (discount).

5. DataStore — Generics

What are Generics?

Generics let you write a class that works with any type. Instead of writing separate RoomStore, BillStore, etc., you write ONE DataStore<T> that works with any type T.

class DataStore<T extends Serializable> {  // T can be ANY Serializable type
    private List<T> items = new ArrayList<>();

    public void add(T item) { items.add(item); }
    public T get(int index) { return items.get(index); }
    public int size() { return items.size(); }

    // Generic method — U can be any Number type (Integer, Double, etc.)
    public static <U extends Number> double sum(List<U> numbers) {
        double total = 0;
        for (U num : numbers) total += num.doubleValue();
        return total;
    }
}

How it's used:

  • DataStore<Bill> billHistory = new DataStore<>() — stores Bill objects
  • DataStore.sum(listOfDoubles) — generic method adds up any list of numbers
  • <T extends Serializable> is a bounded type — T must be Serializable

6. Bill — Wrapper Classes

What are Wrapper Classes?

Java has primitive types (int, double, boolean, char) and their object equivalents (Integer, Double, Boolean, Character). The Bill class uses wrapper classes to demonstrate boxing/unboxing.

class Bill {
    private Integer roomNumber;      // Integer instead of int
    private Double baseAmount;       // Double instead of double
    private Double totalAmount;
    private Boolean isPaid;          // Boolean instead of boolean
    private Character roomCategory;  // Character instead of char

    Bill(Room room) {
        // AUTOBOXING: primitive → Wrapper (automatic)
        this.roomNumber = room.getRoomNumber();  // int → Integer
        this.isPaid = false;                      // boolean → Boolean

        this.taxAmount = baseAmount * 0.12;       // 12% GST
        this.totalAmount = baseAmount + serviceCharge + taxAmount;
    }

    // UNBOXING: Wrapper → primitive (automatic)
    public int getRoomNum() { return roomNumber; }  // Integer → int
    public boolean paid() { return isPaid; }       // Boolean → boolean

    // BOXING: explicit Wrapper usage
    public void markPaid() { isPaid = Boolean.TRUE; }
}

Bill calculation: Base amount (price × days) + service charge (varies by room type) + 12% GST tax = total.

7. BookingQueue — Producer-Consumer Pattern

What is Producer-Consumer?

One thread (producer) adds items to a queue. Another thread (consumer) takes items out and processes them. wait() pauses a thread until something happens. notify() wakes up a waiting thread.

class BookingQueue {
    private final Queue<BookingRequest> queue = new LinkedList<>();

    // PRODUCER — adds a booking request
    public void addRequest(BookingRequest request) throws InterruptedException {
        synchronized (this) {       // SYNCHRONIZED BLOCK — only one thread at a time
            while (queue.size() >= MAX)
                wait();             // WAIT — pause until space available
            queue.add(request);
            notify();               // NOTIFY — wake up the consumer
        }
    }

    // CONSUMER — takes a booking request
    public synchronized BookingRequest getRequest() throws InterruptedException {
        while (queue.isEmpty())     // SYNCHRONIZED METHOD
            wait();                 // WAIT — pause until something is added
        BookingRequest r = queue.poll();
        notify();                   // NOTIFY — wake up the producer
        return r;
    }
}
A restaurant kitchen. The waiter (producer) puts order slips in the queue. The chef (consumer) picks them up and cooks. If the queue is full, the waiter waits. If the queue is empty, the chef waits.

What does this class do?

This is the main class that creates the GUI (graphical user interface). It extends Application (required for JavaFX), creates all the screens (login, admin, guest), and handles user interactions.

10.2 Background Thread (Multithreading)

private void startBookingProcessor() {
    // RUNNABLE INTERFACE — defines what the thread does
    Runnable processor = () -> {         // LAMBDA EXPRESSION
        while (running) {               // run() method body
            if (!hotel.getBookingQueue().isEmpty()) {
                BookingRequest req = hotel.getBookingQueue().getRequest();
                hotel.bookRoom(...);
                Thread.yield();          // YIELD — let other threads run
            }
            Thread.sleep(500);           // SLEEP — pause for 500ms
        }
    };

    bookingProcessor = new Thread(processor);  // THREAD CLASS
    bookingProcessor.setDaemon(true);          // Dies when app closes
    bookingProcessor.start();                  // START — begin running
}
